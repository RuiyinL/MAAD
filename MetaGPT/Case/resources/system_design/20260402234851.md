## Implementation approach

We will use Python with FastAPI for the web interface and API endpoints due to its high performance and async support. SQLAlchemy will manage database interactions with SQLite for simplicity and portability in a local hospital server context. Asyncio will handle concurrent periodic polling of patient devices. A rule-engine service will validate vitals against configurable thresholds. Alerts will be logged and pushed to the dashboard. Security will be handled via API Key middleware. We will simulate analog devices using a random data generator service since physical hardware protocols are unspecified.

## Program call flow


sequenceDiagram
    participant M as Main
    participant DB as Database
    participant DS as DeviceSimulator
    participant ME as MonitorEngine
    participant AS as AlertService
    participant UI as NurseDashboard
    
    M->>DB: Initialize Tables
    M->>ME: Start Background Poller
    loop Every Period (e.g., 5s)
        ME->>DS: read_data(patient_id)
        DS-->>ME: VitalRecord
        ME->>DB: save_record(record)
        ME->>ME: check_vitals(record)
        alt Vitals Out of Range
            ME->>AS: create_alert(patient_id, msg)
            AS->>DB: save_alert(alert)
            AS->>UI: Push Notification (WebSocket)
        else Vitals Normal
            ME-->>ME: Continue
        end
    end
    UI->>M: GET /api/patients
    M->>DB: query patients
    DB-->>M: PatientData
    M-->>UI: JSON Response
