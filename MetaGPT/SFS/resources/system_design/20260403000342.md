## Implementation approach

Due to Flash deprecation, we will migrate the client-side to HTML5/JavaScript using React for UI state and Framer Motion for animations (replacing Flash tweens). The backend will use Python Flask for the Admin Tool and API, with SQLite for data persistence. This ensures browser compatibility without plugins. We will resolve the input contradiction by standardizing on Multiple Choice for consistency, with a specialized 'Fraction Builder' UI component for any required numeric input to prevent syntax errors.

## Anything UNCLEAR

1. Flash Deprecation: The original requirement specifies Flash, but modern browsers do not support it. The architecture assumes migration to HTML5/JS is authorized. 2. Input Method: There is a conflict between 'multiple-choice' and 'fraction input for velocity'. The design assumes Multiple Choice for most questions, with a specialized UI component for numeric fraction input if strictly required by pedagogy. 3. Deployment: It is unclear if teachers have server access to run the Python backend or if this should be a purely static site with JSON editing. The current design assumes a hosted web application.
